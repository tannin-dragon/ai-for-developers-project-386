# Правила коммитов (Conventional Commits)

Проект следует спецификации [Conventional Commits v1.0.0](https://www.conventionalcommits.org/en/v1.0.0/).

## Формат

```
<type>(<scope>): <описание>
```

- **type** — обязательный тип изменения (см. ниже).
- **scope** — опциональная область (см. ниже), в круглых скобках без пробела.
- **описание** — краткое, повелительное наклонение, на русском языке.
  Рекомендуемая длина — до ~72 символов. Без точки в конце.

### Типы

| type | Когда использовать |
|---|---|
| `feat` | Новая функциональность |
| `fix` | Исправление бага |
| `refactor` | Изменение кода без изменения поведения |
| `docs` | Документация и комментарии |
| `test` | Тесты |
| `ci` | Настройка CI, конфигурация сборки/запуска |
| `chore` | Служебные изменения (зависимости, служебные файлы) |
| `build` | Изменения, влияющие на сборку |
| `perf` | Оптимизация производительности |
| `revert` | Откат коммита |

### Scope

Scope — область изменения, из числа используемых в проекте:

- `contract` — контракт TypeSpec/OpenAPI
- `backend` — API (public/backend)
- `frontend` — SPA (public/frontend)
- `e2e` — E2E-тесты и их инфраструктура
- `ci` — GitHub Actions и CI-compose
- `auth` — вход и права владельца

Пример: `feat(backend): добавить отмену бронирования`.

### Breaking changes

Несовместимые изменения контракта/API помечаются в footer:

```
feat(contract): изменить формат времени слотов на offset-datetime

BREAKING CHANGE: поле startTime теперь в UTC со смещением
```

## Примеры

Хорошо:

- `feat(backend): реализовать блокировку слотов владельцем`
- `fix(frontend): сохранять Idempotency-Key при повторной отправке формы`
- `docs: обновить README по запуску`
- `test(e2e): покрыть сценарий записи гостя`
- `ci: запуск E2E-тестов в GitHub Actions`

Плохо:

- `Updated the thing` — не по спецификации, описано неопределённо
- `feat: добавлена новая функция` — можно конкретнее, описано в прошлом
- `fix` — без `:` и описания
- Смешивание нескольких типов в одном коммите без разделения
